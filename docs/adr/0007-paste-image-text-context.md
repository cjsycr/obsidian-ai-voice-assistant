# ADR 0007: 图片粘贴——文本上下文注入而非 UserInputImage 协议

- **状态**: 已接受
- **日期**: 2026-07-20

## 背景

决定如何在聊天输入框中处理粘贴的图片。

## 方案

**将图片信息作为文本描述注入到系统上下文中，而非使用 `UserInputImage` 协议。**

- 用户粘贴图片时，保存到 vault 缓存目录
- 发送时，在 XML 上下文块中添加 `<attached-images>` 标签，描述图片路径、MIME 类型、尺寸
- 让 Codex 使用 fs 工具直接从本地路径读取图片
- 不修改 `send()` 方法签名（通过 `pendingAttachments` 属性传递）

## 备选方案

- **`UserInputImage` 协议**：将图片路径作为 `{ type: "image", url: string }` 传入。更规范，但需要修改 `send()` 签名，且只支持支持该协议的模型
- **Base64 内嵌**：将图片编码为 base64 嵌入文本。所有模型都支持，但 token 消耗巨大

## 后果

- 所有模型都支持（不需要 `UserInputImage` 协议支持）
- 不需要修改 `send()` 方法签名
- 多占用少量 token（图片描述文本）
- Codex 需要用 fs 工具读取图片，多一步文件操作
- 缓存图片在发送后自动清理，不占用磁盘空间
