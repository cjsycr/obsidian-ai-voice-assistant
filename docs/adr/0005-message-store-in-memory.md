# ADR 0005: 消息存储——纯内存 + 重建，不持久化

- **状态**: 已接受
- **日期**: 2026-07-15

## 背景

决定如何存储和管理对话消息历史。

## 方案

**消息只在内存中维护，不持久化到磁盘。**

- `NoteService` 维护一个 `messages: ChatMessage[]` 数组
- 切换笔记时，通过 `rebuildMessagesFromTurns()` 从 Codex 服务器重建历史
- 所有消息操作（删除、多选、翻译、重新生成）都在内存数组上操作
- 关闭插件时消息丢失，下次打开时从 Codex 重建

## 备选方案

- **持久化到 `data.json`**：下次启动时立即可见，但 `data.json` 会迅速膨胀（每条消息都有完整内容）
- **持久化到 vault 内的 Markdown 文件**：可读性好，但同步复杂，且与 Codex 的 turn 历史可能不一致

## 后果

- 冷启动时（切换笔记）需要等待 Codex 返回历史，约 1-3 秒
- 没有磁盘写入，插件大小不受消息数量影响
- 导出功能需要从内存中提取，不影响持久化层
- 审批消息通过 `approvalArchive` 做跨 session 持久化（仅审批决策，不包含完整消息）
